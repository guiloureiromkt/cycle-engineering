# Naming contract (read before touching anything)

Marketplace: `cycle-engineering` (repo name). Plugin: `cycle`. Install: `claude plugin marketplace add guiloureiromkt/cycle-engineering` then `claude plugin install cycle@cycle-engineering`. Local during build: `claude plugin marketplace add <path to this working copy>`.

## Names
- Skills (own, 10): `cycle:using-cycle`, `cycle:intent`, `cycle:research`, `cycle:spec`, `cycle:plan`, `cycle:build`, `cycle:test`, `cycle:deploy`, `cycle:maintain`, `cycle:evolve`.
- Skills (bundled copies from obra/superpowers, MIT, 8): `cycle:brainstorming`, `cycle:writing-plans`, `cycle:executing-plans`, `cycle:subagent-driven-development`, `cycle:tdd`, `cycle:verify-before-done`, `cycle:parallel-agents`, `cycle:worktrees`.
- Skills (bundled, other): `cycle:gauntlet` (Shumer/robonuggets, CC BY 4.0).
- Skills (own, rewritten in English, 4): `cycle:verification-gate`, `cycle:task-graph`, `cycle:adoption-filter`, `cycle:constraints` (the last one carries an external credit too — `CREDITS.md`, Addy Osmani's `constraint-driven-development`, MIT — where the first three carry none).
- Commands: `/cycle`, `/cycle:init`, `/cycle:triage`. Agents: `verifier`, `devils-advocate`, `council`, `joker` (the Mule).
- Any `cycle:<name>` referenced anywhere must exist as `skills/<name>/SKILL.md` (`tests/refs.test.mjs` enforces). Bundle it or rewrite the line.

## Files in a user repo
`intent/`, `research/`, `specs/`, `plans/`, `evals/`, `.cycle/` (`config.json`, `gate.json`, `council.json`, `release-approval`, `work/<intent>/`, `work/.stop-warned`; the untracked state that every worktree of a repository shares lives in `<git-common-dir>/cycle/`: `release-approval`, `gate/gate.log`).
`.cycle/work/<plan>/run.md` is the ledger of a plan's execution (`cycle:executing-plans`, `cycle:subagent-driven-development`): versioned, kept after the run, the record the owner and the retro read. Its first lines are a header; in unattended mode the header carries `mode: unattended`, the owner's sentence verbatim (`requested_by:`), the plan's task ids (`tasks:`), the start time, the budget and the branch. Its last line is `Finished: …` or `Stopped: <which stop> — <what is needed>` when the run ends. `.cycle/work/<plan>/.run/` beside it is the run's scratch (briefs, test logs, review packages) and ignores itself.
`research/<name>.md` is committed next to `specs/` and `plans/`, not under `.cycle/work/`, because it authorizes the spec (the same reason the intent is committed). Its evidence (screenshots) lives under `research/<name>/`.
`/cycle:init` creates ONLY `.cycle/` (config.json, gate.json, work/.gitkeep, .gitignore) and the CLAUDE.md block. It never copies templates. Skills read templates from the plugin root printed by the session hook (`plugin root: <path>`).
CLAUDE.md block lives between `<!-- cycle:start -->` and `<!-- cycle:end -->`; init and uninstall operate only inside the markers.

## Frontmatter
Keys: `type`, `status`, `author`, `date`, `origin`, `intent`, `research`, `spec`, `depth`, `accepted_by`, `approved_by`, `gates`, `council`, `joker`.
Statuses: intent `draft|accepted|closed` · research `draft|done` · spec `draft|approved` · plan `draft|accepted`.

## Magic strings
- Commit message containing `plan: unchanged` or `[plan-ok]` satisfies plan-sync.
- `.cycle/work/<intent>/snapshot.md` modified less than 60 minutes ago (mtime) satisfies snapshot-guard.
- Release: env `RELEASE_APPROVAL` or `.cycle/release-approval` containing today's date (YYYY-MM-DD); since 0.9.2 the file a refusal asks for is `<git-common-dir>/cycle/release-approval` (the repository's git directory, shared by every worktree), and the checkout's own `.cycle/release-approval` still works for that checkout; a file that is a symlink, or sits behind one, is never read. It is valid through the end of that day in the owner's timezone: the machine's own zone, or the zone in `timezone` only on a machine at UTC+0 (that file is the agent's to write, so on the owner's machine it cannot move the owner's day); `RELEASE_APPROVAL` stays unbounded. Written by a human outside the agent; `protect-cycle` blocks the agent from writing it or removing `.cycle/`.
- While plugin `ciclo` 0.1.2 is installed on this machine, commits in THIS repo that touch non-.md files carry `(plano: sem mudança)` or stage `plans/`. After `cycle` 0.2.0 is installed: `(plan: unchanged)`.

## Config (`.cycle/config.json`)
```json
{ "gates": "lite", "stateful": false, "method_repo": null, "protected_branches": ["main"],
  "models": { "advocate": "inherit", "council": "sonnet", "verifier": "sonnet", "sweeps": "haiku", "research": "inherit", "critic": "inherit", "joker": "sonnet" },
  "knowledge": [], "timezone": null }
```
- `gates`: `lite` (default) = devil's advocate always; council SUGGESTED to the user in one question when a trigger lights (money, hours, permission, schema, destructive data, user surface, or more than 8 files change), otherwise skipped and recorded as skipped in the plan. `full` = advocate and council always.
- `models`: passed as the `model` argument when dispatching agents. `sweeps` is the cheap pass-1 of `cycle:intent`; `research` is the stage-2 researcher. Missing `models.sweeps` = `haiku`; missing `models.research` = `inherit`.
- `knowledge`: list of `{name, kind: notebooklm | vault | folder | url, id, areas: []}` the research stage queries when `areas` match the intent. Missing key = empty list. The main session's model is the user's choice; the plugin never changes it.
- `products`: list of repository paths (absolute, or `~`-relative) whose `.cycle/work/*/retro.md` the weekly routine and `scripts/retro.mjs --repeats --across` read, in addition to the repository they run in. Missing key = `[]`. A path without `.cycle/work/` is reported as `not found`, never fatal. A retro with the same cycle name **and** content as one already read (a worktree copy) is counted once; `--since YYYY-MM-DD` keeps retros whose last commit is on or after the date (an uncommitted retro counts as today) and the header prints read/kept/findings per repository, worktrees not read, and sibling repos with a `.cycle/work/` that are not listed. Meaningful only in the method repository (`method_repo: "."`); a product repo leaves it empty.
- `timezone`: an IANA zone, used for the approval's date only on a machine at UTC+0 (a runner, a VPS); a machine with its own zone keeps it, because this file is the agent's to write. An invalid name, and a name the machine did not take, are reported in the refusal.
- `stateful: true` makes production deploy require a restore test newer than 30 days (`.cycle/work/<intent>/restore-test.md`).
- `method_repo`: `null` in every product repo; `"."` only in the repository that holds the cycle itself. Two things read it: the weekly routine (`docs/routines/weekly-evolve.md`) opens there, and `cycle:deploy` refuses to publish a repo whose `method_repo` is `"."` without a gate run pasted in the session (deterministic and free; see "The gate") — because there, a skill edit is a change to the method everything else is judged by.
- `.cycle/gate.json`: `{ "patterns": [] }` — repo-specific deploy commands, lowercase substring match.

## Council seats (`.cycle/council.json`, template in `templates/`)
- `seats` (seven, `always: true`, in speaking order): **Minimalist** first — is this the shape of what was asked, or the shape of what is now possible; then the five custodial seats (user, maintainer, payer, security, operator); **Pollyana** last — look again at what already exists before inventing, then a route with its cost, or an honest no with the smallest change that would open one. A seat may carry `lines` (default 5; the two named seats have 10), which the resolver's `cost_hint` sums. `pool` (`{id, triggers, knowledge, skill, brief}`) is **ordered by trigger precision** (legal, data, commercial, cx first; the prose-matchers content and brand-voice last), because the cap cuts from the end. `cap` (9), `joker` (`enabled`, `domains`), `scenarios` (`horizons`, `paths`). Missing file = the template's defaults. A repo file that lacks a seat the template has gets a warning on stderr and a `warnings` array in the resolver's JSON — `/cycle:init` never overwrites an existing `council.json`.
- Resolution is a script, not prose: `scripts/resolve-seats.mjs plans/<x>.md [--extra ids]` matches triggers as whole words against the plan's **subject** — the `**Goal:**` line with its wrapped continuation, and the bodies of `## Files that change` and `## Proof` — with fenced blocks and code spans dropped, URLs dropped whole, paths split into their segments and their file names dropped, and whitespace collapsed. It then sits the `always` seats, then lit pool seats in pool order up to `cap`, and prints seats, dropped (with reason), `warnings`, a summary line and a cost hint. `--print-subject` prints what the matcher saw and nothing else.
- A plan with neither subject heading is matched **whole** and the resolver says so in `warnings`: an old plan degrades to the previous behaviour, never to silence, and never to a one-sentence subject. An unclosed code fence and a near-empty subject each get their own sentence, because an authoring slip and an old template are different problems.
- A trigger is a phrase about a product subject, never a word the method itself uses. `contract` was the file name `docs/CONTRACT.md`, `table` was "the risks table", `tracking` was a line the plan template gives every plan: across the 21 plan files in this repository on 2026-09-20, those ten words seated **106** pool reviewers, almost none of them about the plan under review. Subject matching left **24**, of which 17 were seats with something to say and 7 were named residuals. Both are a dated reading, not a standing claim: this repository's own plans are in that corpus, so writing a plan about coupons moves the count.
- `cycle:plan` pastes the `summary` line **and** every `warnings` entry — a warning nobody reads is the defect it was written to report. Where no JavaScript runtime exists, which is every eval sandbox, the same rule is applied by hand against the subject only, and the run says that it did.
- `subject()`'s section names are pinned to `templates/plan.md`. Renaming a section there without changing the resolver reverts every new plan to whole-text matching; the two change together.
- A `skill` names a host skill the cycle never bundles (Anthropic's knowledge-work plugins: `claude plugin marketplace add anthropics/knowledge-work-plugins`); when absent the seat says "lens not installed; general practice". A `knowledge` id must exist in `config.knowledge`; a knowledge-backed seat summarises and never quotes sensitive content verbatim into the plan.
- The joker is the Mule: dispatched separately, in a fresh context, on `models.joker`, **after** the risks table (advocate + pre-mortem + council rows) is committed; its shock must be absent from that table. The scenario seat writes no weights on futures and leaves `Signposts:` lines that the plan carries under `## Signposts` and `cycle:maintain` reads.

## The gate (`npm run gate`, `scripts/gate.mjs`)
- **The publish guard (2026-10-16).** `production-gate` runs it first, on every path (legacy and fallback included), gated session or not. It knows the method's public repository as `owner/repo` tails (`remoteTail` in `_lib.mjs`: host ignored, case-insensitive, `.git` and slashes stripped) from the plugin manifest beside the hook file (`homepage`), from `.cycle/config.json → publish.remote` and `publish.previous_remotes` of the session's and the segments' repositories, from the `origin` of any method repository it sees, and from the baked upstream `guiloureiromkt/cycle-engineering` (a fork sets `publish.remote`). It judges by where git would push, not by the shape of the text: for a segment with `git … push` it collects every directory the command can point git at (the segment's cwd, `-C`, `--git-dir`, `GIT_DIR=`, a `(cd X`/`pushd X` earlier in the command) and reads their remotes with an argv, never a shell; a URL or `--repo` on the line is read directly. Any of those with such a tail, or `gh repo sync` / `gh release create|upload|edit|delete` / `gh pr merge` / a writing `gh api` naming the tail or run without `--repo` in a directory whose remote has it, is a publish of the method: denied outright outside a method repository, and inside one allowed only with that repository's approval naming the publish (today's date, and "publish" or the manifest's version), never through the substring patterns. A method repository here is `method_repo: "."` **and** a manifest whose `homepage` is one of the tails. A computed remote token (`$(…)`) with no resolvable remote denies; a deny logs only to directories that already have `.cycle/`. MCP GitHub tools do not pass through this hook and are out of scope. `scripts/publish.mjs <ref>` prepares the clone under `.cycle/work/publish/pub/` (ignored by `.cycle/.gitignore`), moves the local tag to the commit it will push, and never pushes.
- Runs before a publish, not on a pull request: this repository has none. **Deterministic and free since 2026-09-22: it never calls the paid runner.**
- Sequence: a clean tree (an uncommitted change has no date, and the package is the committed tree) → `npm test` → base resolution (`git describe --tags`; **no base is a failure, never a pass**) → the commit-shape rule (no commit touches both `evals/NNNN-` and `skills|agents|hooks|scripts|templates`) → the coverage map → the RED→GREEN record rule → the package → exit.
- `evals/coverage.json` maps every method file to one of three things: a list of case ids, `{tests: "<file>"}` when a unit test covers it deterministically, or `{uncovered: "<reason>", since: "<date>"}` — declared debt, printed on every run and counted by the weekly routine. A file mapped by **nothing** fails the gate.
- **The RED→GREEN record rule.** For every changed method file mapped to cases, at least one covering case's `case.meta.md` has a commit in `<base>..HEAD` whose author date is on or after the file's latest change. The gate reads the git fact; the prose of that commit says the run (result folder, score, kept workspace) **or says "no run, and why"** — a declared waiver, the same shape as declared debt, read by the verifier of the cycle that wrote it and tested by the next monitor run of the case. `CONTRIBUTING.md`'s "no baseline, no review" is this rule, made mechanical.
- **The package is `git archive HEAD`.** `.gitattributes` marks the working copy's private folders `export-ignore` (`intent/ research/ specs/ plans/ .cycle/ CLAUDE.md .gitignore .gitattributes`, anchored at the root — eval fixtures carry their own `intent/` and `plans/`, and those ship). The gate extracts it into a temp dir, runs `npm test` there (the shipped suite skips, with a reason, the tests that read working-copy artifacts), and fails on any file containing this machine's home path. What the gate tests is what the publish ships: one definition.
- **The paid suite is a monitor.** `npm run evals` and `npm run evals:full` keep their flags, their ceiling and their ledger (`evals/results/cost-log.md`); the weekly routine runs them, or a person does. A red case there is a finding: it opens an intent through `cycle:maintain`, or a branch fixing the case when the case is what is wrong. It never blocks a tag. Five reds blocked the 0.7.0 publish over three attempts; four were an `llm` judge over a plan a run had grown, the runner printing its long-file warning each time and the gate obeying the vote anyway; US$26.93 for a tag that never came.
- **A judge's verdict is a finding, never a score that stops a tag.** The runner's score is the runner's; this repository does not reweigh it. **A judge reads a file, never the chat.** An `llm` grader's `focus` is `{source: file, path: <a file the run produced>}`; `last_message` and `trace` are rejected by `tests/refs.test.mjs`. A claim with no artifact gets a deterministic grader (`tool_used`, `file_exists`) or is named as an accepted gap in `case.meta.md`; a claim already proven by a deterministic grader does not also get a judge. A `max: 0` grader is only as good as the `min: 1` grader beside it — if the host stopped logging a tool call, the `min: 1` graders go red suite-wide, the `max: 0` ones go quietly green. Precedents: `0010` (2026-09-13) and `0005` (2026-09-17), both a haiku judge voting 3–0 against a correct run; nine cases carried the shape when the rule was written, two surveys undercounted them, the standing test found them.
- `--threshold` and `--max-cost-usd` live in `package.json`'s `evals` scripts, not in the gate's. They are the owner's numbers: an agent may propose a change in an intent, never make one as a side effect.
- **The shared state directory (2026-10-17).** `hooks/_lib.mjs` `stateDir(repo)` returns `<git-common-dir>/cycle` when git answers, the common dir is named `.git`, `repo` itself is the top level of its checkout, and that checkout is registered (the main worktree, or a linked one whose `<common>/worktrees/<name>/gitdir` back-link names its `.git`, absolute or relative). The release approval is looked up there first, then in the checkout's own `.cycle/`; `gate.log` is written there, each line ending with `@<checkout>`. **Permanent rules, not a transition:** the two-place lookup stays; these cases are not shared by design and fall back to the checkout's own `.cycle/`: a sub-folder of a checkout, a bare repository, a separate git dir, a `.git` file forged to point into another repository. A swapped shared folder (a symlink, or a plain file) is not a fallback: the gate refuses outright and says so. A linked checkout git no longer lists, or lists at another path, gets a `problem` line (session start and refusal); a repair from a mount or container view must not be run from there. `readApproval` refuses a symlink and a file whose real path is not where it claims; `protect-cycle` normalises Write/Edit paths and follows the nearest existing folder through symlinks, and refuses a Bash command that names `.git/cycle` (doubled slashes and `./` included) unless it is plainly read-only; a command that reaches the folder without naming it (`cd .git; cd cycle; ...`, a glob, a path built at run time) is not caught, as for `.cycle/`.
- **The approval's rule (2026-10-17).** `hooks/_approval.mjs`: the day is the owner's (the machine's own zone; `timezone` only at UTC+0; else UTC, said aloud), built from numeric date parts and padded in code; a file passes with a `YYYY-MM-DD` token equal to that day. The refusal leads with a problem or a refused file, then what it expects, where it looked and why each file fails; it never tells the reader to edit `.cycle/config.json`. A use window with a record and a move aside was planned and cut (three new revival routes in the final review); an approval still covers its whole day, as before. See "Release" above.
- Two paid run shapes remain: **baseline** (`--ablation with-without` on a changed skill's case, which is the RED→GREEN the CONTRIBUTING asks for) and **full** (`npm run evals:full`, three runs with the ablation arm, weekly and before a minor tag). The gate is not a run shape any more.

## The weekly routine (`docs/routines/weekly-evolve.md`)
That file is the definition, not a description of one: the prompt, the working directory, the tool list with a reason per forbidden command, what it reads, what it writes, the "did not complete" artifact written **before** the work starts, and the rule that a weekly full run and a pre-tag full run never both fire in the same week (`evals/results/cost-log.md` is how it knows). The routine proposes — a branch for a docs fix, an intent for everything else — and never merges.

## "The owner" is a role, and it needs a second person
Everything outward-facing in this method waits on one sentence from a human: the intent's acceptance, the spec's approval, the plan's acceptance, `.cycle/release-approval`, the publish itself, the triage order, and the gate's threshold and cost ceiling. Today that human is one person. If he is away for two weeks, nothing breaks and nothing ships — the cycle simply stops at every gate, which is the failure mode of a method that works.

So the role is named here, separate from the person: **the owner** accepts intents and plans, approves specs, writes the release approval, orders the triage, and sets the gate's numbers. A repository using this method names its owner and **one designated backup** in its own `CLAUDE.md`, with the backup's authority stated plainly — usually everything except a production release. An agent never fills either slot, never writes an acceptance in someone's name, and never reads "the owner would have said yes" into a silence.

## Hooks (Node, via `hooks/run.sh`)
- Every command-judging gate resolves the repository first (`gateRepo`, `hooks/_lib.mjs`): the repo the **command acts on** — from a `cd` prefix, a `git|make|env -C` flag, one level of nested shell (`bash -c`, `ssh host "…"`), or the working directory the host sends in the payload — walking up to the nearest `.cycle/` and stopping before `$HOME`. **Unresolved is never "allowed": it falls back to the session's own repository.** Neither gated, no gate, no exception. Opt-out = the HUMAN deletes `.cycle/` in their own terminal. `protect-cycle` is the exception that proves the rule: its five string rules about `.cycle` paths run on every payload without resolving anything, because asking would make `cd /tmp &&` a bypass for the hook that exists to stop bypasses.
- **Precedent (2026-09-04 → 2026-09-19), citable against the next convenience default.** The gates keyed themselves to the session's start directory because one session meant one repository. Measured over nine days of real use: 524 of 535 messages came from sessions rooted in a notes vault, four product repositories ran full cycles, **no gate ever fired**, and twelve releases shipped with approval files written where the hook looked instead of where the deploy happened. The first attempt at the fix replaced the session check with the command check and measured *worse*: 56 of 207 deploy-shaped real commands would have become ungated, because "could not resolve" was read as "allow". The rule that came out of it: **a gate may become tighter than it was, never looser — and a default that silently resolves to somewhere convenient is how a guard stops guarding.**
- Exit codes: 0 allow · 1 non-blocking error (stderr shown to the user; the action proceeds) · 2 block (stderr goes to Claude).
- Internal-error rule, same in every hook: git unavailable or not a repo → allow (0); malformed JSON or unreadable config → block (2); node missing → `run.sh` prints "cycle-engineering: node not found on PATH. The cycle gates are NOT active. Install Node >= 18 and restart the session." and exits 1.
- Hook stderr never contains "no such file" or "can't open" (Claude Code downgrades such exit-2 hooks to non-blocking).
- Production defaults (regex on the lowercased command): `--prod\b`, `--target production`, `--env production`, `deploy.*production|production.*deploy`, `gh run rerun`, `gh workflow run`, `wrangler deploy`, `fly deploy`, `railway up`. Not matched: `NODE_ENV=production`, `grep production`, branch names containing production. Push: bare `git push` resolves the current branch (`git rev-parse --abbrev-ref HEAD`); `--tags` allowed; refspec matched with word boundaries.
- Destructive (snapshot-guard): `git reset --hard`, `git clean -f`, `git checkout -- .`, `rm -rf <inside repo>` except node_modules|dist|build|.next|coverage|.cache|.turbo, `drop table|database|schema`, `migrate reset|down|fresh`, `truncate table`.
- Stop reminder (save rule): at most once per 30 minutes per repo, never when `stop_hook_active` is true.
- One `node` process per Bash call: `pre-bash.mjs` dispatches production-gate, plan-sync and snapshot-guard in-process. `protect-cycle.mjs` runs on `Write|Edit|MultiEdit|Bash`. `stop-uncommitted.mjs` on `Stop`. `session-start.mjs` on `SessionStart` (speaks in every repo: one line without `.cycle/`, full state with it, and — in the session's own repository only — the unattended run left open, with its next task). No hook keeps a session running: continuation, when an owner wants it enforced, is the host's `/goal`, typed by the owner.
- **Three outcomes (2026-10-16).** A Bash gate returns `block` (exit 2, stderr), `ask` (stdout JSON `hookSpecificOutput.permissionDecision: "ask"`, flushed, exit 0; the host shows its own prompt) or nothing. Rules run on the executable text of each segment (`commandView` + `walk` in `_lib.mjs`). **Only what is inert leaves the text:** a `#` comment outside `$()`/backticks; the body of a heredoc whose tag is quoted (`<<'E'`); a quoted argument of a sink program (`echo`, `printf`, `cat`, `tee`, `grep`, `rg`, `ag`, `git commit/tag/notes`, `gh pr/issue/release`) with no `$(`, backtick or `$`. **Everything else stays judged, quotes included** (`ssh host "…"`, `bash -c "…"`, `psql -c "…"`, `CMD="…"; $CMD`; an unquoted-tag heredoc body is judged line by line). When a consumer — a program that runs the text it receives: `sh`, `bash`, `zsh`, `eval`, `source`, `.`, `xargs`, `ssh`, `sudo`, `psql`, `mysql`, `sqlite3`, `redis-cli`, `mongo`, `docker exec` — appears anywhere, neither sink quotes nor quoted-tag heredoc bodies are removed (`viewFor` in `_lib.mjs`, the second pass every gate uses). A sink whose segment has a redirect is a writer, not a recorder: its quote stays. A `$'…'` string sets the fallback. A line continuation is a separator only outside quotes and heredoc bodies. `cd`/`-C` are walked on the original text; the branch is seeded **per repository** (the branch it is on when the command starts), follows `checkout -b`/`switch -c` and `checkout <x>`/`switch <x>` only when `refs/heads/<x>` exists, carries across `&&` only, and is unknown after `;` or `||`. A segment whose directory is in no gated repository is judged by the session's (the union rule, never nobody). Hits are collected across repositories and **every hit's repository needs its own approval**. A command whose every segment is a read-only program, with no `$(`, backtick, `<(`, redirect, `-exec` or consumer, skips `gate.json` substring patterns. A match that exists only in removed text, or a push from an unknown branch whose repository did not start on a protected branch, is grey → `ask` in plain words with the command cut to 300 characters. An unknown-branch push from a repository that started on a protected branch denies. A tokenizer failure judges the raw string as before ("parsed as a whole: parser fallback"). Every refusal names the segment and the rule, and says the host may still apply its own permission rules.
- **Nobody present → deny (2026-10-16).** `ask` needs positive evidence of a present human: a literal interactive `permission_mode` in the payload — `default`, `plan`, `acceptEdits` or `auto` (the desktop's default since host v2.1.283; the prompt is still shown there). A missing, renamed, non-string or unknown value, or `CYCLE_UNATTENDED=1` in the environment, turns the ask into a deny with the same reason. `CYCLE_GATE_LEGACY=1`, set by a person, restores whole-string judgement in every gate (the kill switch). A closed stdout on the ask path exits 2.
- **`.cycle/work/gate/gate.log` (2026-10-16).** One line per ask, deny, fallback or legacy decision: ISO time, decision, kind (`segment` · `removed` · `fallback` · `legacy`), rule — never the command text; a URL's `user:token@` is stripped. The folder `work/gate/` carries its own `.gitignore` (`*`), written by the first log line, so it is ignored in every repository whatever the repo-level ignore says; `/cycle:init` also lists `work/gate/`. `cycle:maintain` reads it: count asks **plus** denies (denies fall by construction when they become asks). `ask`, the nobody-present rule and the log are **experimental**: removable by deleting `ask()` in `_lib.mjs` and the grey branches of the three gates, with the fixtures in `tests/fixtures/gate-prose/` as the only contract.
- **Fixtures with a recorded past.** `tests/fixtures/gate-prose/cases.json` carries `before` values recorded by `record-before.mjs` at `recorded_on` (a sha), never by hand; a case that denied before may stop denying only with a `loosening` field saying why, and the suite's never-looser guard checks it.
- **`onFailure: "block"` — dated follow-up (2026-10-16).** The owner's host was 2.1.281; the key needs ≥ 2.1.295 and an untested key could disable every hook. Add `"onFailure": "block"` to the two `PreToolUse` command hooks (`pre-bash`, `protect-cycle`; never `Stop`, never `SessionStart`) once `claude --version` reads ≥ 2.1.295 and a scratch session shows session-start still printing and `git push origin main` still refused. Record in `.cycle/work/2026-10-16-the-gate-judges-commands-not-prose/onfailure-check.md`.
