# Plan: five gates

**Master Brief.** Read `skills/using-cycle/references/master-brief.md` first: if the project has a brief, skip what it already answers; write the decisions taken in §2 and the route and how we'll know in §7.

Nothing is implemented without an accepted plan. Written in plan mode, it passes five gates **on paper** and only then gets `status: accepted` with the acceptor's name. Gates are the agent's work, not questions to the user: "no more questions" turns none off. The only question to the human: acceptance.

## Precondition
An accepted `intent/<x>.md` and an approved `specs/<x>.md` exist and the frontmatter points to them; otherwise the plan is a draft by definition: back to `cycle:intent` or `cycle:spec`, even if the user says "I reviewed it, it's great". At `size: small` the spec may be skipped (`spec: skipped · small` in the frontmatter). At `size: quick` the ten-line plan is written by `cycle:intent` with the intent and runs no gate before the build; the verifier still runs after it. At any size, a stake (`skills/diagnosis/references/stakes.md`) brings the council, without asking, whatever `gates:` says. A sized artifact follows "Gates by size" below; an artifact with no `size:`, or with S, M, L, runs the five gates below, as before. Never give a size to a plan whose intent has none.

## Gates by size
A gate costs less than the change it reviews. For an artifact with a `size:`:
| Situation | Runs before the build |
|---|---|
| `quick` | nothing; the ten-line plan is the review, and the verifier runs after |
| a known path (`path: known`) | graph and loop only; the advocate and the pre-mortem do not run, and the verifier runs after |
| a real decision left after research (`someone-knows`, `nobody-knows`, `split`) | graph, the advocate, the pre-mortem, loop |
| money, people, permission, something irreversible (a stake) | the council joins, without asking, **even on a known path**; and when the advocate does not run, the session writes the plan's risk rows itself ("Risks is never none" below still holds) |
| the Mule | only at project size, and in `gates: lite` it still needs a lit trigger **and** the owner's yes |
An artifact with no `size:` (or with S, M, L) keeps the old path: all five gates, as below.

## Models
Read `.cycle/config.json` → `models`; pass it as the `model` argument when dispatching the advocate, council, verifier, gauntlet critic and research subagents (defaults: advocate `inherit`, council `sonnet`, joker `sonnet`, verifier `sonnet`, sweeps `haiku`, research `inherit`, critic `inherit`). The main session's model is the user's choice.

## Steps
1. **Plan mode.** REQUIRED SUB-SKILL: `cycle:writing-plans`. Ask what breaks, which step is riskiest, what you discarded. Iterate until an engineer who never saw this conversation could implement from it. Technical unknowns (a library to pick, an API limit to confirm) go to a "Technical unknowns" section appended to `research/<name>.md` — decision · justification · alternatives — never a second research file.
2. **Gate 1 · Graph.** Shape of the work (what splits, what is sequential, separate verifier, human gate). REQUIRED SUB-SKILL: `cycle:task-graph`.
3. **Gate 2 · Devil's advocate.** Agent `devils-advocate`, fresh context, always for an artifact with no `size:` (a sized artifact follows "Gates by size" above: no advocate on a known path). The request carries the four paths and nothing about the shape of the answer: the agent's definition sets the format and the closing line, and a request that dictates its own ("return one line each", "say there is no flaw") overrides it (seen in `.cycle/work/2026-09-21-a-judge-over-a-grown-artifact-blocks-every-release/green-run-1-trace.jsonl`; 210 of 228 recovered dispatches did it). Pass `model` from `models.advocate` unless it is `inherit`; then omit `model`. The paths are the plan, the spec, the intent and `research/<name>.md` (at `small`, a skipped spec or research is named as skipped, not invented). **When it returns, first save its message verbatim to `.cycle/work/<intent>/advocate-<round>.md` (round 1, 2, …; one file per dispatch): the plan's rows are what the session kept, the file is what the advocate said. The saved file inherits the plan's confidentiality: the advocate has Bash and its return can paste what it read, so scan it for secret-shaped strings before committing it, and keep `.cycle/work` out of any public repository that does not already commit it on purpose. Then its findings go into the plan's `## Risks` table now, one row each, origin `advocate`, before gate 3 begins — even when the draft is about to be rewritten: the rows move with the rewrite, they do not wait for it, and a rewrite does not delete one (a row that no longer applies says why in its last cell). Write each row as the finding plus "→ changes: <where in the plan>" in the Risk cell (you name the place; if nothing in the plan would change, say so and mark the row 🟡), then Severity, Origin, Cheap test. If it returned "no flaw found", that line goes under the table verbatim, with what it looked for. Under the table, one ledger line: `Advocate ledger (raw-return measure) — round <n>: <findings> findings · changed the plan: pending`; the label keeps it from being compared with the 87% of the older plans, which counted only the rows the session had kept.**
4. **Gate 3 · Pre-mortem.** "Six months later, this failed **because of something inside the plan**. Why?" (a step skipped, a test that lied, a wrong assumption, a migration order). Severity (🔴 🟠 🟡) + a cheap test before building. Events from outside the plan belong to the Mule (gate 4). **Its rows join the same table, origin `pre-mortem`; a finding the advocate already wrote is not a new row — add `pre-mortem` to that row's origin. Commit the plan now**: this is the last point every mode reaches.
5. **Gate 4 · Council and the Mule.**
   - **Resolve the seats by script:** `node <plugin root>/scripts/resolve-seats.mjs plans/<x>.md [--extra <ids the owner named>]` (it reads `.cycle/council.json`, or the plugin template when the repo has none). Paste its `summary` line into the conversation: "council: N seats — …", and every `warnings` entry with it: a warning nobody reads is the defect it was written to report.
     **Where no JavaScript runtime exists** — every eval sandbox: `node`, `npm` and `npx` there are broken symlinks — apply the same rule by hand and say in the conversation that you did. By hand means matching the triggers against the plan's **subject only**: the `**Goal:**` line and the bodies of `## Files that change` and `## Proof`. Never the risks table, never the step prose, never a file path. Matching the whole text is what seated 102 phantom reviewers across 19 plan files before 2026-09-20.
   - **Lite or full.** `gates: lite` (default): the council and the Mule (the Mule only at project size, see "Gates by size") run only when a gate trigger lights (money, hours, permission, schema, destructive data, user surface, more than 8 files) **and** the owner answers ONE question: "Run the council with these N seats (<ids>) and the Mule? <cost_hint>". Record the answer; if no, `council: skipped` and `joker: skipped`. A diagnosis stake skips the question: the council runs, in `lite` too (`skills/diagnosis/references/stakes.md`). `gates: full`: run both without asking. Ask the question; never assume the answer. If it goes unanswered — the session ends, or nobody is there to answer — write `council: pending — <the question, verbatim>` in the frontmatter and stop there: the plan already carries the advocate's and the pre-mortem's rows, committed, and the owner reads them where the reviewer, the verifier and the eval judge will.
   - **Dispatch the council** (agent `council`, `models.council`) with the four paths, the script's JSON (seats with briefs, `knowledge`, `skill`) **pasted verbatim — a summarised brief is a different seat**, and the horizons (the scenario seat writes two or three futures per horizon, one line each). If the script printed `warnings`, paste those too.
   - **Append the council's rows** to the table gates 2 and 3 already wrote, with origin `council: <seat>`; the scenario seat's `Signposts:` lines go under `## Signposts` in the plan. **If the council closed with "all seats agree — treat this as a warning, not a pass", that line goes under the risks table verbatim, naming the two seats**: a council that agreed on everything is a finding about the council, and it belongs in the plan, not in the chat. Commit.
   - **Then dispatch the Mule** (agent `joker`, `models.joker`, default `sonnet`), in its own fresh context, with: the intent's problem statement, the research's recommendation and "What we did not check", the plan's task list and the **committed** risks table, and the `domains` from the script. Never in the same dispatch as the council. Its demand joins the risks table with origin `joker`.
   - **Record** in the plan's frontmatter: `council: [<ids that sat>, scenario]` and `joker: <domain> — <demand or "survives">`.
6. **Gate 5 · Loop.** The bar for "done", verifiable by number or blind comparison; gauntlet yes or no (`cycle:gauntlet`). Fill `## How we'll know`: what number or judgment with a ruler, where it is read, when we look, who reads it.
7. **Risks is never "none"** when money, hours, permission, schema, destructive data or a screen is touched.
8. **Acceptance.** Before asking, replace `pending` in the ledger with the ids of the advocate's rows that changed the plan (`changed the plan: R1, R4`), each checkable against `git diff <commit of the rows>..HEAD -- plans/<x>.md`; the verifier rechecks them. The acceptance is the person's own word in chat, quoted verbatim in `accepted_by`; only after it does the session write `status: accepted`. "No questions", "you decide" and silence never accept: under any of them the plan stays `draft` and the message ends with the one question that remains. For a mentee the question is asked the way `skills/using-cycle/references/mentor-layer.md` says (what I will do, in this order; go ahead?). Commit. Next: `cycle:build`.

**The plan is the record.** Raw gate output may be kept under `.cycle/work/<intent>/` (Rule 3 of the block), but a finding that is not a row in the plan's `## Risks` table was not found: the reviewer, the verifier and the eval judge read the plan, never the work folder and never the chat. On 2026-09-21 a run put nine findings and three blockers into `.cycle/work/discount-checkout/gates.md` and left the plan at `Risks: none` for a change that moves money, while it asked the owner a question about a rewrite; step 7 forbids that plan, and the run had already done the work that would have satisfied it.

## Rationalizations
| Thought | Reality |
|---|---|
| "No more questions, so I implement with guards and note the gaps in the report" | Gaps go in the plan before code, not in the report after. A gate is not a question. |
| "The user approved the plan" | They approved a plan without gates and without an intent: a draft. |
| "I'll handle the risky step in the code" | Name it in the plan. The reviewer checks the diff against the plan. |
| "Who else should look, I'll leave to the verification gate" | That runs after code. Council and advocate run before, when changing is editing text. |
| "I objected silently and moved on" | A silent objection leaves no record. |
