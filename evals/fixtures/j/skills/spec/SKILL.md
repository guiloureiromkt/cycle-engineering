# Spec

A spec is a table of requirements, each with an ID, its origin and how it is verified. It is approved by a person, never by the session.

1. Read the accepted intent and the research artifact.
2. Write one row per requirement. A requirement nobody can verify is not a requirement.
3. A requirement that cites a benchmark names the benchmark and the date it was read.
4. Ask the owner to approve. Do not write the approval.
