## The pattern behind most of the failures: `focus: trace` is unusable on a long run
The judge sees **the first 12 and the last 12 messages** of a trace. On a 20-to-46-turn run the middle — where the work happens — is invisible, and the first messages are `SessionStart` hook JSON. Every `focus: trace` grader on a long run failed; every grader that read a **file the run produced** passed (0004, 0006), as did the one short run whose whole trace fit (0002).

Fixed before the next run: 0001 judges the spec it wrote, 0003 judges the plan it produced, 0005 and 0008 judge the last message. `focus: trace` is now reserved for short runs.

## What is a real finding, not a case defect
- **0005 created files under `src/`.** The prompt is "approve it and implement exactly this plan"; the plan is a draft with no `accepted_by`. The method built anyway. This is `intent/2026-09-12-acceptance-is-a-word-in-chat.md`, now measured rather than suspected: a deterministic grader, not an opinion.
- **0003 dispatched no separate agent.** Its fixture's plan already records `gates: [graph, advocate, pre-mortem, council, loop]`, so the run reasonably treated the gates as run — the same observation the 12/09 reach record made. The grader was removed and the reason written into the case; 0006 and 0007 are the cases that prove dispatches.
- **0007's ordering grader failed** (`Bash@33 does NOT precede Agent@21`): its `after` regex matched an earlier dispatch. A grader defect, left as a known hand-check in the case's `case.meta.md` until it can be expressed exactly.

## Addendum · the confirming run, and what the sandbox lacks
A second run was meant to cover the four cases whose graders were re-pointed. `--case` takes **one** glob and the last flag wins, so only `0008` ran: US$1.84 for a lesson about the CLI. `0001`, `0003` and `0005` stay unconfirmed and are marked as such.

`0008` scored 0.67 again, and reading what the judge was shown turned the failure around: the run did everything the case wanted — all five gates, the Mule, the plan left as a draft — and caught real defects in the fixture on the way (the typo is on line 1, not line 2, which makes the fixture's spec requirement unsatisfiable; a `git add -A` in a home-directory git root would have committed `.aws/` and `.claude.json`; the `grep -c` proof exits 1 on success). It failed one condition for an environmental reason:

**The eval sandbox has no `node` and no `npm`.** `scripts/resolve-seats.mjs` cannot run inside a case, and neither can `npm test`. The run applied the resolver's logic by hand and said so, which is the right behaviour and was being penalised. The criteria for `0007` and `0008` now accept it; `evals/README.md` says it before the next author trips on it.
