# Discount at checkout — implementation plan

**Goal:** `charge()` accepts the coupon code `SET10`, applies 10% in integer cents, rounded once in the customer's favour, refuses to charge zero, and returns the original amount, the discount and the coupon so finance can reconcile. Valid until 2026-09-30, resolved on the server.

**What changed after the gates.** The first draft also shipped a customer-facing banner (`src/copy.js`, Portuguese and English, "marketing brief attached to the intent"). The spec puts the checkout screen out of scope, no brief is attached to the intent, and no file in this repo would render the banner. The banner and its task are gone. The return shape now matches spec R3 instead of `{amount, discount, banner}`. The `customerId` argument, which the draft silently dropped, stays.

## Architecture

- `src/coupons.js` · new. Holds the coupon table and the input validation. Exports `resolveCoupon(code, now)`.
  - Table: `new Map([['SET10', { percent: 10, until: Date.parse('2026-09-30T23:59:59.999-03:00') }]])`. A `Map`, not a plain object, so `__proto__` or `constructor` can never resolve. Expiry is end of day in Brasília time (the campaign and the `pt-BR` locale are Brazilian). This is the only place a date or a percentage is written.
  - `resolveCoupon(code, now)`: validates the input (section below), looks it up, throws `Error('invalid coupon')` when unknown or when `now > until`. Returns `{ code: 'SET10', percent: 10 }`.
- `src/billing.js` · modify. Signature becomes `charge(customerId, amountCents, coupon = null, now = new Date())`.
  - Existing callers keep working: no coupon → `discountCents: 0`, `coupon: null`.
  - `now` is server-side only. The HTTP layer (outside this repo) never forwards a client-supplied date; tests pass it explicitly so expiry is deterministic.
  - Returns `{ customerId, originalAmountCents, discountCents, amountCents, coupon, status: 'charged' }`. `amountCents` is what the card is charged; the three new fields are R3.
- Rounding (R5): `discountCents = ceil(amountCents × percent / 100)` computed in integers: `const p = amountCents * percent; discountCents = Math.floor(p / 100) + (p % 100 === 0 ? 0 : 1)`. One rounding, always up, so the customer never loses the fraction of a cent. No floating point touches money.
- Floor (R4): after the discount, if `amountCents - discountCents <= 0` throw `Error('invalid amount')`. The existing `amountCents <= 0` guard on the input stays.
- No new dependency (intent constraint). `src/settings.js` is not touched.

### Coupon input validation (closes the spec's open concern "cupom vindo do cliente sem validação")

The coupon string arrives from the client. Before lookup, `resolveCoupon` enforces:
1. `typeof code === 'string'`, otherwise throw `invalid coupon` (objects, arrays, numbers, `null` never reach the table; `null`/`undefined` passed to `charge()` means "no coupon" and is handled there, before `resolveCoupon` is called).
2. Normalise: `code.trim().toUpperCase()`. `' set10 '` is accepted as `SET10`; the normalised code is what the return object carries, so finance sees one spelling.
3. Length cap: after trim, 1 to 32 characters, otherwise throw. Nothing large is ever compared or logged.
4. Lookup on a `Map` with `.get()`. Prototype keys are inert.
5. The percent comes from the table, never from the caller (R1, intent "cliente não pode escolher o percentual").

Failed lookups throw; they are not logged here (this repo has no logger). Rate limiting of coupon guessing belongs to the HTTP layer and is out of scope; noted for the deploy checklist.

## Tasks

### Task 1 · `resolveCoupon` with validation and expiry
**Files:** create `src/coupons.js`; extend `tests/run.js`.
- [ ] Tests first, each one a named line in `tests/run.js`:
  - `resolveCoupon('SET10', new Date('2026-09-15T12:00:00-03:00'))` → `{ code: 'SET10', percent: 10 }` (R2 valid)
  - `resolveCoupon(' set10 ', …)` → same (normalisation)
  - `resolveCoupon('SET10', new Date('2026-09-30T23:59:59-03:00'))` → valid; `new Date('2026-10-01T00:00:00-03:00')` → throws `invalid coupon` (R2 expiry, both sides of the boundary)
  - `resolveCoupon('NOPE', …)` → throws (unknown)
  - `resolveCoupon('__proto__', …)`, `resolveCoupon({}, …)`, `resolveCoupon('x'.repeat(33), …)` → throw (validation)
- [ ] Run `npm test`, see the new lines fail, implement, `npm test` green. Commit: `feat(coupons): resolveCoupon with validation and expiry`.

### Task 2 · `charge()` applies the discount and returns the R3 fields
**Files:** modify `src/billing.js`; extend `tests/run.js`.
- [ ] Tests first:
  - `charge('c1', 100)` still returns `status: 'charged'` with `discountCents: 0`, `coupon: null` (backward compatibility, the existing test line survives)
  - `charge('c1', 1000, 'SET10', new Date('2026-09-15T12:00:00-03:00'))` → `{ customerId: 'c1', originalAmountCents: 1000, discountCents: 100, amountCents: 900, coupon: 'SET10', status: 'charged' }` (R1, R3, exact keys)
  - `charge('c1', 1005, 'SET10', …)` → `discountCents: 101`, `amountCents: 904` (R5 half-cent, in the customer's favour; the research's required failing case)
  - `charge('c1', 1, 'SET10', …)` → throws `invalid amount` (R4, floor to zero)
  - `charge('c1', 1000, 'SET10', new Date('2026-10-01T00:00:00-03:00'))` → throws `invalid coupon` (R2 through the public function)
- [ ] Run `npm test`, see them fail, implement in integer arithmetic, `npm test` green. Commit: `feat(billing): charge() applies SET10 in integer cents`.

## Risks

| Risk | Severity | Mitigation | Rollback |
|---|---|---|---|
| Wrong charge amount reaches a card (money). | 🔴 | Integer arithmetic only, half-cent and floor tests, separate verifier. | `git revert` of the Task 2 commit; the repo's rollback command is `none`, so revert is the only path and must be rehearsed before deploy. |
| Coupon accepted after 30/09. | 🔴 | Boundary tests on both sides; date lives in one table. | Revert Task 1 commit, or set `until` in the past in a one-line hotfix. |
| Coupon string used as an attack vector. | 🟠 | Validation section; `Map` lookup; length cap. | Same revert. |
| Finance report reads old field names. | 🟠 | Exact-key assertion; the report is outside this repo and must be told the new names at deploy. | Additive fields, old `amountCents` keeps its meaning (what was charged). |
| Timezone drift on the expiry day. | 🟡 | Expiry pinned to `-03:00` explicitly. | One-line change to the table. |
