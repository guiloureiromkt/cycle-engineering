# Discount at checkout, with the coupon banner — implementation plan (draft · gates run 2026-09-12 · verdict below)

**Goal:** `charge()` applies the SET10 percentage discount in integer cents, and the checkout shows a banner telling the customer the coupon was applied, with the copy the marketing team wrote.

**Architecture:** `resolveCoupon(code, now)` in `src/coupons.js`; `charge()` in `src/billing.js` returns `{ amount, discount, banner }` where `banner` is the customer-facing sentence ("Cupom SET10 aplicado: você economizou R$ X") rendered by the checkout page.

### Task 1: `resolveCoupon`
**Files:** create `src/coupons.js`; test `tests/run.js`.
- [ ] Test: `resolveCoupon('SET10', new Date('2026-09-15'))` → `{ percent: 10 }`; unknown code throws.
- [ ] Implement; `npm test`; commit.

### Task 2: `charge()` applies the discount and returns the banner text
**Files:** modify `src/billing.js`; test `tests/run.js`.
- [ ] Test: `charge(1000, 'SET10')` → `{ amount: 900, discount: 100, banner: 'Cupom SET10 aplicado: você economizou R$ 1,00' }`.
- [ ] Implement in integer cents; `npm test`; commit.

### Task 3: banner copy
**Files:** create `src/copy.js` with the banner sentence in Portuguese and English.
- [ ] The sentence comes from the marketing team's brief (attached to the intent); no other copy changes.

## Signposts
- Day after: a checkout call still shaped `charge(customerId, amountCents)` erroring, or SET10 still validating after 2026-09-30, within hours of release.
- Six months: no coupon-config table by the second campaign's kickoff — the one-cycle-per-campaign cost is real.
- Legacy: any reconciliation script or ticket translating between `amount/discount` and `originalAmountCents/discountCents` — the field mismatch shipped.

## Revision the gates converge on (not applied to the tasks above; applied on acceptance of this revision)
One file, no `coupons.js`, no `copy.js`, no banner. Coupon table `{ SET10: { percent: 10, validUntil: '2026-09-30' } }` inside `src/billing.js`.
`charge(customerId, amountCents, coupon = null, now = new Date())` → `{ customerId, amountCents, status, originalAmountCents, discountCents, coupon }`, with `now` never read from request data.
Tasks: (1) red tests for R1–R5 + half-cent + 1-cent + expired + absent coupon + invalid string, all in `tests/run.js`, committed failing; (2) implement, `npm test`, commit; (3) verifier in fresh context. Decisions still needed from the owner before build: rule at 1 cent (clamp or throw, risk 4); invalid/expired → full price or error (risk 8); discount base confirmed (risk 9); where finance reads the discount (risk 10).
